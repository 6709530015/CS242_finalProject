ที่มาของปัญหา (pain point / ปัญหา ที่เราต้องการแก้ไขคือ?)
นักศึกษาพลาดวันสำคัญ เช่น วันสอบ วันนำเสนอ หรือวันส่งงาน

แนวทางการแก้ปัญหาที่กลุ่มนักศึกษานำเสนอ (กลุ่มเราพัฒนาอะไร?)
ระบบรวบรวมนัดหมาย ที่ช่วยบันทึกและแจ้งตือนนัดหมายสำคัญสำหรับนักศึกษาซึ่งเป็นผู้ใช้งานหลักของระบบ อีกทั้งยังบันทึกผลนัดหมายร่วมกับ Google Calendar ไปด้วย ระบบโซลูชั่นดังกล่าวมี Requirement ดังนี้
1.เพิ่มรายละเอียดนัดหมาย
2.ลบนัดหมายออกจากรายการ
3.แสดงผลวันนัดหมายทั้งหมดที่กำลังจะมาถึง
4.แสดงผลสถานะว่านัดหมายเลยกำหนดการไปแล้วหรือไม่
5.นับจำนวนวันก่อนถึงนัดหมาย
6.แสดงผลการแจ้งเตือนเมื่อใกล้ถึงวันนัดหมายแต่ละงาน
7.แสดงผลกราฟเพื่อดูภาพรวมจำนวนนัดหมายแต่ละเดือน
8.วิเคราะห์จำนวนนัดหมายที่มีต่อเดือน

ประโยชน์ที่จะได้รับหากปัญหาได้รับการแก้ไขโดยใช้ solution ที่นักศึกษานำเสนอ 
1.ผู้ใช้สามารถมองเห็นภาพรวมวันนัดหมายที่มี
2.เพิ่มประสิทธิภาพในการวางแผนเวลาชีวิตมากขึ้น
3.ผู้ใช้ไม่พลาดนัดหมายสำคัญ

สถาปัตยกรรมระบบและแนวคิดการออกแบบ
1.Web UI - Flask framework
2.Server - Python OOP
3.Database - SQLite
4.Data / Library Integration - Request, Pandas, Matplotlib 
5.External Integration - Google Calendar, SQLite

Class Diagram (UML)

ผลการดำเนินงาน
ระบบรวบรวมนัดหมาย มีโฟลเดอร์และไฟล์ในการทำงานหลักๆ ดังนี้
1.Authentication - เชื่อมต่อกับ Google Calendar API ผ่าน OAuth2 เพื่อให้ backend สามารถสร้างและจัดการ event บน Google Calendar ได้
2.Models - เก็บ object ทั้ง 3 class ได้แก่ 
  event.py - สร้างโมเดล Event ที่มีข้อมูลตาม UML
  event_manager.py - จัดการ Event โดยเป็นตัวกลางระหว่าง list ของ Event และ ไฟล์ JSON
  reminder.py - แจ้งเตือนและวิเคราะห์ข้อมูล Event โดยเชื่อมกับฐานข้อมูล SQLite และใช้ Pandas กับ Matplotlib สร้างสถิติและกราฟ 
3.Static - เก็บข้อมูล style.css สำหรับตกแต่ง UI
4.Storage - ฐานข้อมูลแบบ JSON ของ Event โดยเก็บรายละเอียดเพื่อให้ระบบสามารถโหลดกลับมาใช้งานได้ทุกครั้งที่เปิดโปรเจกต์ 
5.Templates - เก็บไฟล์กลุ่ม HTML
  add_event.html - จัดการ event
  base.html - หน้า dashboard ที่เชื่อมกับหน้าอื่นๆ
  index.html - หน้าหลักสำหรับรายละเอียด event
  stats.html - รวบรวมสถิติ event การแจ้งเตือนที่กำลังมาถึง และกราฟสรุปผลต่างๆ
6.app.py - Web Application โดยเชื่อมทั้ง JSON, SQLite, และ Google Calendar API เข้าด้วยกัน 
7.database.py - เชื่อมต่อกับ SQLite database สำหรับเก็บและจัดการข้อมูล event 
8.events.db - ฐานข้อมูล SQLite ที่ระบบ Flask/Reminder ใช้เก็บข้อมูล event 
9.server.py - ทดสอบการเชื่อมต่อกับฐานข้อมูล SQLite (events.db)
	จากการทดสอบระบบพบว่าสามารถทำได้ตาม user flow ที่วางไว้

Business Logic - ระบบคำนวณวันคงเหลือของนัดกมาย ถ้างานไหนกำหนดส่งภายใน 3 วัน จะถูกถึงมาแสดงผลทันที พร้อมแสดงสถานะว่าเป็น “TODAY” หากเป็นงานที่ต้องส่งวันนี้ และ “UPCOMING” เป็นงานที่กำลังจะถึงกำหนด เพื่อให้ผู้ใช้ลำดับความสำคัญได้ชัดเจน
Data Persistence - ใช้ไฟล์ JSON (load_from_json & save_from_json) บันทึกรายการงานเพื่อรักษาความต่อเนื่องของข้อมูล โดยมีระบบ สร้างโครงสร้างข้อมูลใหม่ทันทีหากไฟล์เสียหาย เพื่อป้องกันโปรแกรมค้างและรักษาเสถียรภาพของระบบ
Robustness - มีการกำหนด input validation ใน database โดยกำหนดชนิดข้อมูลที่บังคับใช้ และกำหนดการอนุญาตให้มีค่า NULL หรือไม่ รวมถึงมีการกำหนด exception ในกรณี Login ล้มเหลว และกรณีไฟล์ Json ไม่ตรง format หรือไม่มีไฟล์ดังกล่าว
